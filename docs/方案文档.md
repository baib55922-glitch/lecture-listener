> 版本 v0.1（方案评审稿）· 确认后进入编码阶段

---

## 1. 产品概述

**一句话**：一个常驻后台的安卓 App，用**本地离线语音识别**把老师的话实时转成文字，自动判断"老师是不是提问了"，一旦识别到问题，立刻调用 **DeepSeek API** 在页面底部生成一张可折叠卡片（标题=问题，内容=简明答案），帮助学生秒答水课提问。

**核心流程**：

```
麦克风(16kHz) → Vosk 离线流式识别 → 断句切分(按停顿/静音)
   → 规则预过滤(问号/疑问词/祈使提问) → 候选句交给 DeepSeek 判定
   → 确认是问题 → DeepSeek 生成答案 → 页面底部折叠卡片(问题+答案)
```

**关键原则**：
- 转写 100% 本地，免费、隐私、零延迟；
- DeepSeek 只干两件事：**判断是不是问题** + **回答问题**，用量极小，成本可忽略；
- 全程前台服务常驻：息屏、切后台都继续监听；小米"灵动岛"（澎湃OS 超级岛）胶囊常驻，其他手机通知栏常驻。

## 4. 核心模块设计

### 4.1 录音 AudioRecorder

- `AudioRecord`，采样率 **16kHz**、单声道、PCM 16-bit（Vosk 标准输入）；
- 缓冲 100~200ms 一帧送入识别器；
- 设备支持时开启 `NoiseSuppressor`（系统降噪），设置页提供"教室降噪"开关；
- 麦克风数据只进 Vosk，绝不外传（隐私承诺写进设置页）。

### 4.2 离线识别 Vosk

**模型选择**（两个档位，设置页可切换）：

| 模型 | 大小 | 精度 | 用途 |
|---|---|---|---|
| `vosk-model-cn-0.22`（完整版） | ~1.3 GB | 较好 | 正式使用，首次启动下载 |
| `vosk-model-small-cn-0.22`（小模型） | ~42 MB | 一般 | 快速体验/低配手机兜底 |

- 大模型不打包进 APK（1.3GB 太大），**首次启动时从服务器下载到应用外部目录**，带进度条 + 校验（SHA-256），可断点续传；
- 流式识别：`acceptWaveForm()` 持续喂数据，`getPartialResult()` 拿实时文本（转写区实时滚动显示），句子结束时拿最终结果；
- 内存占用：大模型约数百 MB 级，小模型 <100MB；低配机（4GB 内存）建议用小模型。

### 4.3 断句切分 Segmenter ——"老师这句话说完没有？"

这是体验的关键：切早了，半句话被拿去判定（误判率高）；切晚了，答案出得慢。

策略（三者取先到者）：
1. **Vosk 端点**：Vosk 自带静音判定，检测到停顿会给出 final 结果；
2. **自研静音检测**：实时算 RMS 能量，静音持续 **1.0~1.5s**（可调）判定一句话结束，把当前累积的 partial 文本定为完整片段；
3. **最长句保护**：连续说话超过 **25s** 强制切分，防止老师长篇大论导致片段无限膨胀。

只有"完整片段"才进入问句判定管线，转写区照常实时滚动显示 partial 文本。

### 4.4 问句判定 —— 规则预过滤 + LLM 确认（你选定的方案）

**第一层：正则规则（零成本、毫秒级、挡住 90% 的废话）**

| 类别 | 模式（示例） |
|---|---|
| 问号 | `？` |
| 疑问词 | 什么、怎么、为什么、如何、哪、谁、多少、几、啥、咋、是否、能否、可否、为何 |
| 正反问 | 是不是、对不对、有没有、会不会、能不能、可不可以 |
| 句末语气 | 吗、呢（限句尾） |
| 祈使提问 | 谁来说说、谁来回答、大家(想/思考/讨论/举手)、说说(你/大家/自己)的(看法/想法/观点)、有人知道吗、思考一下 |

**第二层：LLM 确认（只对命中规则的候选句调用）**

候选句 → DeepSeek `deepseek-chat`，要求 JSON 输出：

```
系统提示词（判定用）：
你是课堂监听助手。给你一段老师刚说的话，判断它是否是一个"向学生提出的问题"。
判断标准：是疑问句、或带有提问意图的祈使句（如"谁来说说""大家思考一下"）。
输出严格 JSON：{"is_question": true/false, "question": "规范化后的问题文本"}
规范化：去掉口头语、重复词、语气词（"呃""那个""对不对啊"），合并成一句通顺的问题，保留原意。
若 is_question 为 false，question 输出空字符串。
```

- 设置页提供**"严格模式"**：所有完整片段都送 LLM 判定（更不易漏，稍费一点 token）；
- 防抖：同一片段只判定一次；判定中产生的新片段进队列；
- 漏网之鱼兜底：老师提问不带任何疑问词（如"这道题选什么"——其实带"什么"；真正的极端情况如"π 等于几"由规则覆盖），靠 LLM 层兜底。

### 4.5 DeepSeek 答案生成

**调用细节**：
- Base URL：`https://api.deepseek.com`（OpenAI 兼容 `/chat/completions`），模型 `deepseek-chat`；
- 参数：`temperature=0.3`（答案求稳不求花）、`max_tokens=300`、超时 15s、失败自动重试 1 次；
- Key 保存：`EncryptedSharedPreferences`（加密存储，不落明文），设置页可"测试连接"；
- 官方定价参考：[DeepSeek 模型与价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)（价格很低，详见 §8 成本估算）。

**答案系统提示词**（按你的要求定制：简明扼要、不要称呼）：

```
系统提示词（答题用）：
你是大学课堂上的学生助手。老师刚刚提出了一个问题，你正在站起来回答。
要求：
1. 直接给出答案本身，可附一句简短理由；
2. 全文不超过 120 字；
3. 不要称呼任何人，不要任何客套语（"好的""我来回答""谢谢"），
   不要"根据材料""我认为"之类的套话，开口就是答案；
4. 问题若信息不全，给出最合理的推测答案，不要反问；
5. 术语保留英文缩写（如 API、GDP），其余用中文。
```

用户消息 = 规范化后的问题文本。

### 4.6 卡片与去重

**卡片状态机**：`判定中 → 生成答案中 → 完成 / 失败(可点击重试)`

**去重策略**：
- 规范化（去标点/空格）后，与已有卡片**字符重叠率 ≥ 0.85** 或编辑距离比例 ≤ 0.2 → 视为重复，丢弃；
- 老师重复追问同一问题（5 分钟内）→ 不新建卡片，仅更新原卡片的"追问次数"标记；
- 卡片操作：点标题展开/收起、长按复制答案、右滑删除、工具栏"清空会话"。

## 5. 前台服务与常驻（含小米灵动岛）

### 5.1 服务实现

- `MicListenerService`，Manifest 声明 `foregroundServiceType="microphone"`（Android 14+ 强制）；
- 常驻通知：`setOngoing(true)`，内容动态更新为 `🎙️ 正在听课 · 已识别 N 句`；**生成新问题卡时，通知内容更新为最新问题摘要**（澎湃OS 超级岛会把常驻通知胶囊化显示，用户抬头就能看到问题）；
- 息屏监听：前台服务 + 麦克风类型即满足，无需额外唤醒锁（必要时加 `PARTIAL_WAKE_LOCK` 兜底）；
- 通知渠道"课堂监听"，重要性 `LOW`（不打扰），生成新问题时可选震动提醒（设置开关）。

### 5.2 小米"灵动岛"（澎湃OS 超级岛）适配说明

- 超级岛是**系统级胶囊 UI**：系统会自动把常驻通知/进行中事件渲染成摄像头附近的胶囊，**开发者不需要专用 API**，做好标准前台服务通知即可；
- 首次启动引导页（或设置页"后台保活设置"入口）引导用户完成小米机型的必要设置：**自启动允许、省电策略→无限制、通知权限**；同时在文档中给华为/OPPO/vivo 的设置路径表；
- 由于超级岛展示规则由系统控制，方案上以"标准常驻通知"为基准实现，真机验证胶囊显示效果；若个别机型不胶囊化，通知栏常驻兜底，功能不受影响。
- 参考：[澎湃OS 开发者平台](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2131)

### 5.3 厂商后台限制规避（引导用户，非代码魔法）

| 厂商 | 设置路径 |
|---|---|
| 小米/Redmi | 设置→应用设置→应用管理→本应用→自启动/省电策略(无限制) |
| 华为/荣耀 | 设置→应用→应用启动管理→手动管理→允许自启动/关联启动/后台活动 |
| OPPO/一加 | 设置→电池→应用耗电管理→允许后台运行；权限→自启动 |
| vivo/iQOO | i管家→应用管理→权限管理→自启动；后台高耗电→允许 |

## 6. UI 设计

- **主页**：顶部状态栏（监听中绿点/暂停红点、本次会话已识别句数）；中部转写区（滚动，当前句高亮、字体偏大适合偷瞄）；底部卡片区（**最新卡片在最下方**，生成时自动滚动到可见并自动展开；之前的卡片自动折叠为标题行，点击展开）；
- **卡片**：标题=问题（1~2 行截断），展开后=答案正文 + 底部小字（时间、重试/复制按钮）；
- **设置页**：API Key（密码框+测试连接）、识别模型（大/小）、静音切句阈值、判定灵敏度（标准/严格）、震动提醒、清空会话；
- 深色模式跟随系统。

## 8. 成本与性能估算

**DeepSeek 调用量（一节 90 分钟水课）**：
- 判定调用：规则命中约 30~60 次 × ~300 tokens 输入 ≈ 1.5 万 tokens；
- 答案调用：约 5~15 个问题 × （~50 tokens 输入 + ~150 tokens 输出）≈ 3 千 tokens；
- 合计 ≈ **2 万 tokens 以内，成本远低于 1 元/节课**（具体单价以[官方定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)为准；就算按最高档估算也是几分钱量级）。

**延迟预算**（老师说完问题 → 答案上屏）：
- 断句等待静音：~1.2s（可调）＋ 判定 LLM：~0.5~1s ＋ 答案 LLM：~1~3s ≈ **总延迟 3~5 秒**，水课场景足够。

**功耗**：Vosk 大模型连续识别预计 300~600mA 级（发热可感，正常）；息屏后 UI 不渲染，功耗主要来自识别；小模型功耗约为大模型一半以下。

## 9. 开发里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 | 工程骨架：权限、前台服务、常驻通知、设置页(Key) | 安装后通知栏常驻，Key 能存能测 |
| M1 | 录音 + Vosk 流式识别 + 转写 UI（先内置小模型） | 真机实时出字，转写区滚动 |
| M2 | 断句 + 规则预过滤 + 卡片 UI（先用假数据） | 说"为什么……？"能出卡片 |
| M3 | DeepSeek 判定 + 答案生成 + 去重 + 失败重试 | 完整链路 3~5 秒出卡 |
| M4 | 大模型下载流程、小米保活引导、降噪开关、打磨 | 息屏一节课不断流、不重复出卡 |

> 说明：Vosk 中文模型基于较老的 Kaldi 方案，在**嘈杂教室**环境精度有限（口头语、方言、远场都会掉精度）。方案里已含降噪开关、大模型优先、贴近讲台建议；若实测不达标，备选升级路径是换 **sherpa-onnx（Paraformer 中文模型）**，接口改造工作量可控——这属于风险预案，不阻塞第一版。

## 10. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | 教室噪音导致转写错误 | 系统降噪开关、建议手机放讲台附近、大模型优先；兜底：sherpa-onnx 升级路径 |
| 2 | 学生回答声被误判为老师提问 | 只对"完整片段+规则命中"送 LLM 判定；接受少量误判（卡片可一键删除） |
| 3 | 无问号提问漏检（"谁来说说"） | 祈使提问正则表 + 严格模式开关 |
| 4 | 厂商杀后台 | 保活引导页（§5.3）+ 卡片本地持久化，重开恢复 |
| 5 | Android 15/16 对 microphone 前台服务的时间限制 | 长课时每 ~2 小时自动重建服务；通知提示 |
| 6 | API Key 泄露风险 | 加密存储；绝不进日志 |
| 7 | 大模型 1.3GB 下载失败 | 断点续传 + SHA-256 校验 + 小模型兜底 |

## 11. 待你确认的默认决策

以下是我替你做的默认决定，如无异议我就按此写代码：

1. **UI**：Jetpack Compose（Material 3），单 Activity；
2. **模型策略**：APK 内置小模型（42MB）保证开箱即用，首次启动引导下载大模型（1.3GB）提升精度；
3. **提醒方式**：检测到新问题时仅更新常驻通知（灵动岛/通知栏可见）+ 可选震动；不做语音播报；
4. **历史数据**：第一版只保留本次会话（可清空），不做历史数据库；
5. **答案语言**：跟随问题语言，术语保留英文缩写；
6. **卡片顺序**：最新卡片出现在底部，自动展开，旧卡自动折叠。

确认（或提出修改）后，我进入 M0 编码阶段。
